# 已提交凭据的仓库清理

本仓库曾出现 OA 凭据。即使当前文件已经改成占位符，旧值仍可能存在于 Git 历史和既有克隆中。当前 OA 对接要求继续使用既有 AppKey、AppSecret、SSO Secret，因此本次整改不会在 OA 管理端轮换它们；实际值只能保存在受控的 `deploy/.env` 或部署密钥系统中，禁止重新写入仓库。

现有 OA 凭据已确定长期保留，不安排后续轮换。继续使用已进入 Git 历史的凭据属于已接受的残余风险；历史清理只能减少后续扩散，不能使已暴露的值重新变得安全，因此必须依靠 `.env` 文件权限、主机访问控制、日志脱敏和使用审计降低风险。

模型配置属于业务保留数据。升级、清库迁移或重建环境时，必须完整迁移 `model_configs` 及旧版
`system_config` 中的模型 ID、API 地址、API Key 和启用状态，不得用占位符覆盖数据库中的有效配置。
模型 API Key 只能进入受控迁移包或部署密钥存储；文档、示例、日志和仓库仍只能出现占位符。

## 操作顺序

1. 冻结主分支写入并通知所有协作者。
2. 确认现有 OA AppKey、AppSecret、SSO Secret 已从受控的 `deploy/.env` 注入，且文件权限为 600；不要改变其值。
3. 轮换应用签名、管理员、Redis、PostgreSQL、MinIO 凭据；重启相关服务，确认旧值失效。OA 三项凭据除外。
4. 创建仅安全负责人可访问的加密仓库镜像备份。
5. 使用 `git filter-repo --replace-text <受控替换规则文件> --force` 清除所有分支和标签中的旧值。替换规则文件不得提交到仓库。
6. 运行 `gitleaks detect --source . --log-opts=--all` 和 `bash scripts/check-secrets.sh`。
7. 经双人复核后强制推送全部重写的分支和标签。
8. 删除旧远端引用；要求所有协作者删除旧克隆并重新克隆，不允许 merge 旧历史。
9. 核查 OA、网关、Nginx 和应用日志中旧凭据的使用记录。

历史重写会改变所有受影响提交的哈希。本文件只提供操作规程；应用部署脚本不会自动执行历史重写或远端强推。
